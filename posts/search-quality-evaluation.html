搜索与推荐评估：CTR、GSB 与上线决策

点击率描述用户行为，GSB描述同一道问题上结果的相对优劣。把两者放进同一套评估流程，才能分清“更容易被点击”“回答更好”和“是否值得上线”。

先分清：行为、偏好与绝对质量

搜索、推荐和生成式问答都需要评价效果，但不同指标回答不同的问题。一次点击可能来自相关内容，也可能来自诱人的标题、靠前的位置或答案不完整；一次偏好胜出可能只是措辞更自然，核心事实仍然错误。

观察维度典型指标能支持的判断
用户行为CTR、转化率、停留或任务完成用户在实际展示和交互条件下做了什么
相对偏好GSB、净胜率同一问题上，实验结果相对基线好在哪、差在哪
绝对质量事实正确率、可用率、核心信息覆盖即使两版都不好，也能判断是否达到任务要求
服务代价延迟、失败率、推理成本体验收益是否伴随不可接受的服务退化

点击不直接证明满意度，GSB胜出也不等于事实正确。例如生成式搜索把答案直接展示给用户，任务完成后不再点击外链，CTR下降仍可能伴随体验提升。因此要先确定产品目标，再选择主指标和护栏。

CTR怎么算：分母和提升幅度

CTR（Click-Through Rate，点击率）的基本公式是：

CTR = 点击次数 / 曝光次数

公式简单，事件口径更关键：曝光是服务端返回、实际进入可视区域，还是达到最短可见时长？点击是否去重？机器人流量、重复刷新与埋点缺失如何处理？这些规则要在实验前固定，两组一致。

搜索中还要区分结果粒度CTR与有点击Query占比：一条Query可以展示多个结果，前者以结果曝光为分母，后者以Query为分母，不能换用同一个名称进行比较。

假设示例：对照CTR为4.5%，实验CTR为4.8%。绝对变化是+0.3个百分点；相对变化是 (4.8% − 4.5%) / 4.5% ≈ +6.67%。这组数字只演示计算，不是某项实验的实际收益，也不能单凭均值认定显著。

CTR预估模型学习用户、内容和上下文的点击概率，能支持排序；预测更准是否带来线上收益，还取决于候选供给、排序目标、曝光机制和业务约束。在CPC广告中，点击也要结合单价、预算、转化和无效流量判断价值。

A/B测试：偏差与显著性

实验需要比较同一业务范围下的策略。常见做法是按用户稳定随机分桶，避免同一用户频繁在两组间切换；具体随机单元应与产品和干扰关系匹配。实验周期要覆盖业务波动，并检查流量分配、埋点和两组样本构成是否异常。

  • 位置偏差：靠前结果更容易被看见和点击。对比结果质量时，应观察相同展示位置的切片，或通过受控实验识别位置影响。
  • 曝光偏差：日志只包含被展示的候选，未曝光内容没有点击标签。直接从日志泛化到所有候选会受原策略选择影响，需要按任务考虑探索数据或偏差校正。
  • 流量构成变化：大盘均值会受人群、意图、品类和终端占比影响。切片有助于定位问题，但大量事后挑选切片也会增加误报。
  • 短期吸引力：标题改变可能提高CTR，却增加快速退出或投诉。应同时看转化、任务完成等后续信号，避免只追逐点击。

统计显著性需要样本量、方差和置信区间等信息。若按用户随机化，同一用户的多次曝光通常相关，不能把所有曝光都当作独立样本；推断或重采样应尊重随机单元。实验前约定主指标、观测窗口和分析方式，避免反复查看到“显著”就提前停止。

统计显著也不保证业务意义：非常大的样本可以检出很小的差异。是否值得发布，还要看改善幅度、成本和负向风险。

GSB三档与可选的五档标注

GSB（Good / Same / Bad）让评估人员在同一Query的基线与实验结果间做相对比较：G为实验更好，S为持平，B为实验更差。它比直接比较不同标注者的1—5分更容易校准，但仍需要明确的任务标准。

为区分实质改善与轻微变化，可以采用以下五档方案。S+、S−是可选标注设计，并非所有业务通用的标准；边界应由任务的核心信息、正确性和可用性要求决定。

档位相对实验结果示例与判断边界
G实质改善纠正关键错误、补齐完成任务所需的信息
S+轻微改善核心信息相同，表达或结构更符合要求
S持平按当前评价标准，没有足够证据区分优劣
S−轻微退化存在边缘遗漏或冗余，但核心任务仍可完成
B实质退化关键事实错误、严重遗漏或无法完成任务

这里的“实质改善”是标注规则中的程度描述，不是统计显著性的结论。两版都错误也可能被评为S，所以还应独立记录绝对正确性、可用性和严重风险；不能因为相对持平就判定达标。

净胜率：保留分母与持平样本

三档评估设有效评测单元总数为 N = G + S + B，一种常用的净胜率定义为：

胜率 = G / N
败率 = B / N
净胜率 = (G − B) / N

例如一组假设的100条结果中，30胜、50平、20负：胜率30%，败率20%，净胜率+10%（胜率与败率相差10个百分点）。若排除持平后计算 G / (G + B) = 60%，得到的是有胜负样本内的条件胜率，分母不同，不能与全样本胜率混用。

五档应先报告完整分布，再明确汇总方式；此时N为五档样本总数，包含G、S+、S、S−、B。若把G/S+视为胜、S−/B视为负，净胜率为 [(G + S+) − (S− + B)] / N；若只关心实质变化，可以事先把S+/S−归入S。不同映射对应不同问题，不能在看完结果后选择更好看的规则。

不论采用哪种口径，保留各档数量、有效分母、切片和置信区间。一次净胜率为正可能仍有较大不确定性；少量严重退化也可能被大量轻微改善掩盖，需单独分析。

一轮可复核的人工评估

  1. 先写标准：明确任务、核心正确性与可用性要求，给出G/S/B或五档的边界例和严重错误定义。
  2. 构建样本：代表性样本反映目标流量，困难/长尾/风险样本用于专项诊断。两类样本分开报告；定向挑出的bad case不能直接估计全量收益。
  3. 生成配对：同一Query对应两版结果，保存模型和策略版本。除本次有意改变的变量外，尽量控制其他条件，并记录无法完全对齐的差异。
  4. 盲评和随机左右：隐藏模型身份、随机交换左右展示；保留必要上下文，让评估人员按同一任务条件判断。
  5. 校准与复核：用典型样本统一尺度，抽取重叠标注检查一致性，对分歧和严重错误复核。模型Judge可辅助筛查，但需核验其偏差，不能只留下容易判断的样本。
  6. 统计与归因：报告档位、分母、切片与不确定性；对B/S−区分知识、检索、推理、指令遵循和表达问题，形成下一轮可验证的改进假设。

净胜率可把每个有效Query记为 +1 / 0 / −1 后求均值，再以配对Query为单位bootstrap估计置信区间；重采样时必须把两版结果保留在同一配对中。若多个样本来自同一用户或问题簇，还应考虑簇内相关性。

样本规模由预期差异、变异程度、覆盖要求和资源决定，没有“100—500条即可上线”的通用阈值。挑战集可以持续补充，也应保留稳定的对照集与代表性评测，避免每轮换题后仍把数字当作同口径比较。

把评估结果转成上线决策

上线判断应基于预先定义的业务目标和护栏，综合离线相对偏好、绝对质量、线上行为与服务成本。下面的组合是排查思路，具体门槛需要业务另行约定。

观察到的组合下一步判断
CTR改善，GSB和绝对质量稳定检查后续转化/任务完成与成本，再评估是否扩大实验
CTR改善，但事实错误或严重B增加暂缓放量，核对点击吸引力是否掩盖质量退化
GSB改善，但CTR下降排查展示、延迟、意图差异，也检查是否因答案已直接满足需求
指标接近持平、区间较宽判断证据是否足够，检查覆盖和实验设计，不强行归为成功或失败

可复核的结论应同时交代：基线与实验策略、样本和流量范围、统计口径、变化幅度、置信区间、严重退化与代价。CTR提供行为证据，GSB帮助解释差异，绝对质量和服务护栏决定这些收益是否可接受。
