强化学习基本框架

强化学习（Reinforcement Learning, RL）研究的是一个智能体（Agent）如何通过与环境（Environment）的持续交互，在"试错—反馈"中学习一套让长期回报最大化的行为策略。以训练一只小狗坐下为例：发出指令后小狗做出反应，做对了给零食（奖励），做错了给一点惩罚，重复足够多次后，小狗会自发地趋利避害——这是强化学习最朴素的直觉起点，也是"奖惩机制"这个核心思想的来源。

概念符号说明
Agent（智能体）—待训练的决策主体，在 LLM 语境下通常就是模型本身
Environment（环境）—智能体所处并与之交互的外部系统
State（状态）s_tt 时刻智能体观察到的环境信息
Action（动作）a_t智能体在状态 s_t 下做出的决策
Reward（奖励）r_t环境对动作 a_t 的即时反馈，是一个标量
Policy（策略）π_θ(a|s)决定"在状态 s 下应该做什么"的函数，由参数 θ 控制
Value（价值）V(s) / Q(s,a)基于当前状态对未来累积回报的预测

Policy 和 Value 对应智能体的两种能力：Policy 负责在动作之前做判断（"这一步该怎么做"），Value 负责基于状态对未来做预测（"照这样下去大概能得多少分"）。这两者的分工，在后文的 Actor-Critic 架构里会被直接实体化为两个独立训练的神经网络。

价值函数、回报与贝尔曼方程

要让 Value 具备"预测"能力，需要先定义清楚它预测的到底是什么。智能体在一条轨迹上获得的不是单步奖励，而是折扣累积回报（Return）：

Gt = rt + γrt+1 + γ2rt+2 + ... = Σk=0∞ γkrt+k
G_t：从时刻 t 开始的累积折扣回报
γ ∈ [0,1]：折扣因子，越接近 1 越重视长期回报

状态价值函数 Vπ(s) 和动作价值函数 Qπ(s,a) 分别衡量"处于某状态"和"在某状态下执行某动作"的长期期望收益：

Vπ(s) = Eπ[Gt | st=s]
Qπ(s,a) = Eπ[Gt | st=s, at=a]
Vπ(s)：策略 π 下从状态 s 出发能获得的期望回报，即 Value 模型要预测的量
Qπ(s,a)：策略 π 下在状态 s 执行动作 a 之后能获得的期望回报

这两个价值函数满足一个递归关系——贝尔曼方程（Bellman Equation）：当前状态的价值，等于"即时奖励"加上"折扣后下一状态的价值"：

Vπ(st) = E[ rt + γVπ(st+1) ]

这也是 Critic 模型训练的理论基础：它不需要等到整条轨迹结束才知道对错，而是可以按贝尔曼方程做单步自举（bootstrapping），用真实奖励与自己历史预测之间的差异（TD 误差）不断修正预测——这正是价值方法（Value-based）的核心工作方式。

策略梯度与 Actor-Critic

强化学习有两条经典技术路线。价值方法（Value-based）先学准 V(s) / Q(s,a)，再通过"选价值最高的动作"间接得到策略；策略梯度方法（Policy Gradient）则反过来，直接用神经网络参数化策略 πθ(a|s)，让梯度直接作用在策略参数 θ 上。LLM 的强化学习对齐场景几乎都走第二条路——动作空间（词表）巨大，枚举所有 Q(s,a) 并不现实，直接对策略做梯度上升更自然。

判断"哪些动作该被强化"需要一个信号，这就是优势函数（Advantage Function）：

Aπ(s,a) = Qπ(s,a) − Vπ(s)
衡量"在状态 s 下选择动作 a，比这个状态下的平均水平好多少"：A > 0 说明这个动作值得被强化，A < 0 说明应该被抑制

用优势替代原始回报作为权重，是策略梯度降方差的标准手段，更新方向由策略梯度定理给出：

∇θJ(θ) = Eτ~πθ[ Σt ∇θlog πθ(at|st) · Aπ(st, at) ]
J(θ)：策略的期望回报目标；直接用蒙特卡洛采样得到的 G_t 做权重方差很大，用一个额外训练的价值网络去估计 baseline 并计算优势，可以显著降低更新方差、加快收敛

这就是 Actor-Critic 架构的由来：Actor（策略网络）负责生成动作，Critic（价值网络）负责评估状态、辅助降方差，二者配合完成一次更新。PPO，正是这套 Actor-Critic 思想在大模型对齐场景下的具体实现，核心理解可以概括为"自己做题、自己预测、对答案后修改"。

PPO：角色分工与训练目标

在 LLM 对齐场景下，完整的 PPO 训练涉及四个模型，分工明确：

模型名称角色它是谁更新参数作用
Actor（演员）Agent需要训练的 LLM是负责生成回答，所有 LLM Loss 最终都是为了让它变强
Critic（评论家）教练Value Model是预测当前状态大概能得多少分，辅助 Actor 减少方差
Reward（裁判）考官奖励模型否（冻结）给 Actor 的回答打出真实的 Reward 分数
Ref（参考）镜子SFT 原始模型否（冻结）防止模型"忘本"，计算 KL 散度，确保 Actor 不偏离初始语言能力太远

Critic：预测"照这样写下去还能得多少分"

Critic 与 Actor 结构相似（Transformer + Value Head），但输出是一个标量价值而非下一个 token 的概率分布，输入是当前已生成的文本，输出是对未来累积奖励的估计。它与 Actor 一起训练，用真实奖励和自己历史估计之间的 TD 误差（对应上一节的贝尔曼方程）不断修正预测。

Reward：给出真实但静止的分数

Reward 模型通常是一个基于 Transformer 的分类器，输入是 prompt + response，输出一个标量分数；它用人工标注的偏好数据（两个回答，人选择哪个更好）通过对比学习训练，训练完成后冻结参数，不再更新——它定义"什么是好"，但本身不参与优化。

核心区别：Reward 模型是真实的外部反馈（基于人类偏好），固定不变，用来定义"什么是好"；Critic 模型是内部的价值估计，随 Actor 一起进化，用来让学习过程更平滑高效。

Ref：防止模型"忘本"的锚点

Ref 就是训练开始前的 SFT 原始模型，冻结参数，不参与训练。它的作用是提供一个"行为锚点"——通过 KL 散度约束 Actor 的新策略不要偏离这个锚点太远，防止模型为了讨好 Reward 而丢掉基础的语言能力。

PPO 核心机制：KL 约束、裁剪目标函数与优势估计

PPO 的优化目标是在"奖励最大化"与"和 Ref 模型保持接近"之间做平衡：

Max(总目标) = Reward(期望奖励) − β × KL散度(Actor 新策略 ‖ Ref 参考策略)
KL 散度衡量新策略（Actor）与参考策略（Ref）分布的差异，差异越大扣分越多；β 是可调节系数，决定"不忘本"约束的强度。优化时需要让期望奖励上升、KL 散度下降，才能让总目标变大

另一个关键机制是裁剪（Clip）。PPO 是 on-policy 算法，希望用旧策略采集的数据更新新策略，但更新幅度不能太大。为此需要比较同一个 token、同一个位置在新旧策略下的生成概率比值：

r(θ) = πθ(at | st) / πold(at | st)
分子是当前 Actor 在状态 s_t 下选择动作 a_t（某个具体 token）的概率，分母是采集数据那一刻（旧策略）对同一个 token 的概率。这个比值只针对实际被采样到的那个 token，而不是对整个词表分布做比较

当 r(θ) 过大，说明新策略在这个动作上概率提升过猛，需要被限制。PPO 的裁剪目标函数（Clipped Surrogate Objective）把优势 Â_t 和这个比值结合起来：

LCLIP(θ) = Et[ min( rt(θ)·Ât, clip(rt(θ), 1−ε, 1+ε)·Ât ) ]
ε：裁剪范围超参数（常取 0.1~0.2），clip 把 r_t(θ) 截断在 [1−ε, 1+ε] 区间内；取 min 保证目标函数是真实目标的悲观（下界）估计，避免单步更新幅度过大

优势 Â_t 的具体估计方式，PPO 通常采用 GAE（Generalized Advantage Estimation），结合多步 TD 误差按 λ 加权求和：

δt = rt + γV(st+1) − V(st)
ÂtGAE = Σl=0∞ (γλ)l δt+l
δ_t 即 TD 误差（单步贝尔曼残差）；λ ∈ [0,1] 控制偏差与方差的权衡——λ=0 退化为单步 TD 估计，λ=1 接近蒙特卡洛估计

Critic 自身的优化目标则是让预测价值逼近真实回报，用均方误差衡量：

Value Loss = (真实回报 − 预测价值)2
该损失只更新 Critic 参数，不直接影响 Actor；真实回报来自 Reward 模型给出的最终得分与后续步骤奖励的累计

训练流程速览

前向：① Actor 逐 token 生成回答 → ② Reward 对完整回答打出真实分数 → ③ Critic 在每一步预测"照这样写下去大概能得多少分" → ④ Ref 在同样输入下给出参考概率，用于后续计算 KL。

后向：① 用真实奖励和 Critic 估计计算优势 Â_t → ② 用新旧策略概率比值和 Â_t 计算裁剪损失 → ③ 加上与 Ref 的 KL 惩罚项 → ④ 用 MSE 更新 Critic → ⑤ Actor 损失（裁剪项与 KL 惩罚的组合）与 Critic 损失分别反向传播，更新各自参数。

PPO 的最终目标，是让 Actor 写出既受人类偏好（高奖励）、又不偏离原始语言能力（小 KL）的回答，同时借助 Critic 提供的优势信号，让每一步更新都保持稳健（clip 限制）。

从 PPO 到更轻量的对齐算法

PPO 需要同时维护 Actor、Critic、Reward、Ref 四个模型，训练链路复杂、显存开销大。围绕"如何砍掉一部分模型、保留核心思想"这个问题，后续出现了一系列变体。GRPO（Group Relative Policy Optimization，群组相对策略优化，DeepSeek 团队提出）是其中最具代表性的一支：它去掉了 Critic，对同一个 prompt 一次性采样一组（如 4 个）回答，用组内奖励的均值和标准差做标准化，直接得到每个回答的相对优势，替代原本需要 Critic 估计的 Â_t：

Âi = (ri − mean(r1, ..., rG)) / std(r1, ..., rG)
r_i 是同一 prompt 下第 i 个回答的奖励得分，G 是组内回答数量；标准化后的 Â_i 替代 PPO 中由 Critic 估计的优势，再套用同样的裁剪目标函数和 KL 惩罚项更新策略

DPO（Direct Preference Optimization）走的是另一条路——连 Reward 模型也一并去掉，直接在人工标注的偏好对（chosen/rejected）上做一个二分类式的优化，不需要在线采样。DAPO 在 GRPO 基础上引入动态采样和解耦裁剪，应对长思维链场景下的多样性和训练效率问题；ORPO 则是一种无需参考模型的偏好优化方法。几种方法与 PPO 的核心差异可以归纳为：

方法优势估计是否需要 Critic是否需要采样训练数据
PPOGAE（用 Critic 估计）需要在线奖励模型打分
DPO直接比较偏好对不需要离线人类偏好对
GRPO组内相对标准化不需要在线奖励模型打分

这些算法在大模型对齐中的具体应用——包括 DPO 的 LoRA 双适配器工程实现、GRPO 相比 PPO 的显存优化路径——可参考另一篇《大模型微调与对齐全流程》。
