LLM 推理性能指标详解：TTFT、TPOT 与 ITL

大模型推理服务的性能评估离不开三个核心延迟指标——它们分别刻画"响应快不快""生成快不快""生成稳不稳"，是做推理系统选型和优化时必须拆解清楚的基本功。

📅 2026-09-24
LLM推理 性能优化 vLLM

为什么是这三个指标

评估一个 LLM 推理系统，不能只看"总耗时"这一个笼统数字。用户对延迟的感知在生成的不同阶段是不一样的：第一个字出得快不快、后续吐字流不流畅、吐字节奏稳不稳定，背后对应的是完全不同的系统瓶颈。TTFT、TPOT、ITL 正是把"总耗时"拆解到这三个维度上的标准指标，分别对应 Prefill（预填充）和 Decode（解码）两个阶段的不同计算特征。

TTFT（Time To First Token）

定义：从请求发出到收到第一个输出 Token 的时间，核心影响因素是 Prompt 预填充（Prefill）阶段的计算效率。

TTFT = Nprompt / θprefill + Tfixed
N_prompt：输入 Prompt 的 Token 数量
θ_prefill：Prefill 速度（Token/s），依赖硬件并行计算能力（如 GPU 的 FLOPs）
T_fixed：固定开销，包括网络延迟、框架初始化等

示例：Prompt 100 Token，Prefill 速度 500 Token/s，固定开销 10ms：TTFT = 100/500 + 0.01 = 0.21 秒。

优化方向

  • 提高硬件并行度（如使用 A100/H100 GPU）
  • 优化 Prompt 编码，压缩冗余 Token
  • 使用更高效的推理框架（如 vLLM 的 PagedAttention）

TPOT（Time Per Output Token）

定义：解码阶段平均每个输出 Token 的生成时间，核心影响因素是自回归生成的计算量和内存带宽。

TPOT = (E2E − TTFT) / (Noutput − 1)
E2E：端到端总延迟  TTFT：首 Token 延迟  N_output：输出 Token 总数
通常为常量，除非受内存带宽限制波动

示例：生成 50 个 Token 共耗时 2.5 秒：TPOT = (2.5 − 0.2) / 49 ≈ 0.047 秒。

优化方向

  • 量化模型（如 FP16/INT8 降低计算量）
  • 优化 KV Cache 内存访问（如 FlashAttention）
  • 批处理（Batching）提升吞吐量，但可能增加单请求 TPOT

ITL（Inter-Token Latency）

定义：连续两个输出 Token 之间的实际间隔时间，核心影响因素是解码阶段的串行依赖性和系统调度开销。理想情况下 ITL ≈ TPOT，但实际会因框架调度或资源竞争而偏高。

ITL = Decode Phase Time / (m − 1)  (m ≥ 2)
m：解码阶段产出的 Token 数量

示例：若 TPOT 为 50ms，叠加 10ms 调度开销：ITL = 50 + 10 = 60ms。

优化方向

  • 减少调度延迟（如使用 TensorRT-LLM 等专用推理后端）
  • 避免 CPU-GPU 同步阻塞

三者的关系与系统性能

指标影响维度说明
TTFT用户体验较短的 TTFT 让用户感知"响应迅速"
TPOT生成速度直接影响 Token/s，尤其在长文本场景下
ITL稳定性波动过大会导致生成过程"卡顿"
E2E Latency = TTFT + TPOT × Noutput

综合示例

指标示例值说明
TTFT0.2 秒首 Token 响应较快
TPOT0.05 秒生成速度约 20 Token/s
ITL0.06 秒存在约 10ms 的调度开销

测量工具与方法

  • 框架内置工具：如 vLLM 的 metrics 接口、PyTorch Profiler
  • 自定义脚本：记录请求-响应时间戳，逐阶段计算延迟
  • 压测工具：用 locust 或 k6 模拟并发请求，统计指标分布
这三个指标不是孤立的：优化 TTFT 主要是压缩 Prefill 的计算路径，优化 TPOT/ITL 主要是改善 Decode 阶段的内存带宽利用率和调度效率。评估一个推理系统时，把总延迟拆到这三个维度上，才能定位到真正的瓶颈在哪一层。
