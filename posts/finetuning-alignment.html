大模型微调与对齐全流程：从 SFT 到 DPO / GRPO

Pre-train 得到的 Base Model 并不具备对话能力。从 Base Model 到一个真正"能对话、说人话"的对齐模型，中间要经过一条完整的流水线——本文梳理这条流水线上每一环的本质差异与工程取舍。

📅 2026-09-24
SFT DPO GRPO LoRA

总体脉络

通过 Pre-train 训练出的 Base Model 只会"接龙"，不具备对话能力。我们使用 FFT（全量微调）或 PEFT（如 LoRA、QLoRA、Adapter、Prefix，甚至解码时干预的 Proxy-tuning）对 Base Model 做 SFT（监督微调），使其变成 Chat Model。之后通常再用 RLHF、DPO、GRPO 等对齐算法（期间依然可以结合 LoRA 等 PEFT 技术）对 Chat Model 做人类偏好对齐，最终得到高质量的对齐模型。

ORPO 等新算法可以跳过独立的 SFT 阶段，直接进行对齐，或者把两者合而为一。

Pre-train 与 SFT 的 Loss 核心差异

两者在数学本质上完全相同，都是交叉熵损失，真正的差异在于计算范围（Mask 掩码）。

Pre-train（预训练）：全量计算，自监督接龙

输入纯文本，模型对每一个词都执行"预测下一个词"的任务，所有位置的 Loss 均参与平均，目的是学习语言规律与世界知识。

例：输入「天王盖地虎」，目标是「盖地虎宝塔」。模型对"盖""地虎""宝塔"等每一个预测都计算 Loss（如 avg(−log0.56, −log0.42, −log0.37)）。

SFT（监督微调）：掩码计算，只学回答

输入问答对，模型同样做下一个词预测，但通过 Mask 强制屏蔽 Prompt（提问）部分的 Loss，只有 Assistant（回答）部分的 Loss 参与反向传播，目的是学会遵循指令对话。

例：输入「[user]天王盖地虎[assistant]」，目标「宝塔镇河妖<EOS>」。"天王""盖""地虎"不计算 Loss（Mask 为 −100），仅计算"宝塔""镇""河妖"和 <EOS> 的 Loss。

为什么 −log(P) 就表达了交叉熵

交叉熵衡量的是"模型预测分布"与"真实分布"的差距。在语言模型中，真实分布是 One-hot 编码（正确词概率为 1，其他词概率为 0）。根据交叉熵公式 H = −Σ P真实·log(P预测)，由于其他词真实概率为 0，求和后只剩一项：−log(预测正确词的概率)。概率越低，−log 的值就越大，对模型的"惩罚"就越重。

一句话记忆：Pre-train 是"接龙游戏，错一个词都要挨打（全算）"；SFT 是"课堂考试，只改作答部分（Mask 提问）"；交叉熵则是"给正确词打分，概率越低，罚得越狠"。

前置概念：参数更新策略 vs 训练阶段，是正交关系

必须明确：FFT/PEFT（参数更新策略）与 SFT/RLHF/DPO/GRPO（训练阶段/优化目标）是两个相互独立、可以自由组合的维度。LoRA 等 PEFT 技术并非 SFT 专属，它贯穿于 SFT 和偏好对齐（如 DPO、GRPO）的全流程。

打个比方：烹饪方式（炒、炖、烤）和食材（猪肉、牛肉、蔬菜）是正交的——你可以"炒猪肉"，也可以"炖猪肉"，还可以"炒蔬菜"。烹饪方式不限制食材，食材也不限制烹饪方式，它们互不干扰。

注：Proxy-tuning 严格来说不是参数微调，而是解码时（Decoding-time）通过修改大模型 logits 分布来实现干预，目标大模型权重不动。

SFT 阶段：让模型"会说话"

  • 目标：让 Base Model 学会指令遵循，具备一问一答的对话能力
  • 数据：成对的 QA 数据（如 Alpaca、ShareGPT 格式）
  • 手段：可用 FFT（全量微调，成本极高），也可用 PEFT（高效微调）——冻结大部分参数，仅微调少量参数（如 LoRA、QLoRA、Adapter、Prefix-Tuning），大幅降低显存并缓解灾难性遗忘

偏好对齐阶段：让模型"说人话、说好话"

SFT 后的 Chat Model 虽然能对话，但可能产生幻觉、有害内容或答非所问。对齐算法旨在用人类偏好数据（或奖励信号）进一步优化模型。

DPO（Direct Preference Optimization，直接偏好优化）

数学本质：绕过显式的奖励模型，直接利用偏好数据（chosen/rejected）。其损失函数利用策略模型和参考模型对 chosen 和 rejected 回答的生成概率（logps）之差，通过 Sigmoid 函数映射并计算交叉熵损失，最大化 chosen 的相对概率。

工程痛点：标准 DPO 需要同时加载策略模型和参考模型，显存翻倍。

LoRA DPO 工程绝技：加载一个共享的基座模型，在其上挂载两个 LoRA 适配器——一个可训练（train），一个冻结作为参考（reference）。训练时通过切换适配器计算概率，将"模型级对比"降维为"适配器级对比"，让消费级显卡也能跑大模型 DPO。

踩坑提示：若 SFT 用了 QLoRA，需先合并权重得到未量化模型，再加载新 LoRA 做 DPO。

GRPO（Group Relative Policy Optimization，群组相对策略优化）

核心思想：取消 PPO 中庞大的价值网络（Critic），通过组内相对比较估计优势。

流程：对每个 Prompt 生成一组（如 8 个）回答 → 奖励模型（或规则函数）打分 → 计算组内奖励的均值和标准差得到优势值 → 结合 KL 惩罚项更新策略模型。

模型加载数量的显存优化路径

  • 标准 GRPO 需加载 2 个模型（策略模型 + 奖励模型），相比 PPO（4 个模型）已大幅节省显存
  • 参考模型为何可选：参考模型原本用于计算 KL 惩罚，防止模型偏离 SFT 太远。但若奖励信号极度客观（如数学规则），或直接取消 KL 惩罚（如 DeepSeek-R1 的 β=0），就可以安全省去参考模型
  • 工程降维至 1 个模型：若用数学/代码等规则函数替代奖励模型，或用 LoRA 共享基座（挂载策略和参考适配器），则只需加载一个基础模型

特殊演进与例外

  • ORPO / SimPO：打破"先 SFT 再对齐"的两段式范式，将 SFT 损失和偏好对齐损失合并为单一损失函数，一步到位完成训练
  • RLHF (PPO)：传统的对齐方式，流程复杂（需策略、价值、奖励、参考四个模型），是 DPO 和 GRPO 试图改进的"前辈"

一句话终极总结

从 Base Model 到最终对齐模型，是一条"Pre-train 打底 → SFT（结合 FFT/PEFT）赋予对话能力 → 偏好对齐（DPO/GRPO 结合 LoRA 等 PEFT）提升回答质量"的流水线。参数更新策略和训练阶段是两个正交的维度，理解这一点，才能在实际项目里灵活组合出符合显存预算的训练方案。
